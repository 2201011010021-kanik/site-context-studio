# Data and format expansion plan

The urban:EXPORT feature list is a useful product benchmark, not a representation of this app's present coverage. This document records which capabilities are real, which are proposed, and the evidence needed before offering them to users.

| Capability | Current implementation | Next implementation and acceptance check |
| --- | --- | --- |
| Building footprints and heights | Live Overture capture; source height, floor estimate, unknown, optional conceptual scenario remain distinct. Roof attributes are now retained when present in new captures. | Add building parts with parent IDs and `min_height`; test overlaps and roof geometry against source records before calling anything LOD2. Official regional LOD2 feeds each need their own schema, rights and coverage review. |
| Terrain and contours | Mapzen Terrain Tiles are downloaded to a georeferenced GeoTIFF; a resampled DEM mesh joins buildings in DAE and drives 3D/illustration contours. | Add region-specific surveyed or lidar bare-earth terrain only where open redistribution permits. Record vertical datum, source resolution, void treatment and age. Generate contours from full-resolution grid for print exports. |
| Roads and bridges | Source transportation centrelines are retained. Analysis reports clipped centreline length; the separate 1 km urban tool estimates local choice and mapped-junction walking reach with explicit limits. | Read width/level/bridge attributes where present, and derive road surfaces only from evidence with clear assumptions. Verify grade-separated crossings in sample sites. |
| Water, parks, trees | Mapped Overture water and land use; no invented trees. | Add source-backed land cover or tree inventories by region. Satellite tree detection requires a licensed image source, inference pipeline, confidence and error review before rollout. |
| Area selection | Free polygon capture and a separate movable 1 km square for urban analysis; current job budgets and provider throughput limit large regions. | Add other square/circle/rectangle helpers in the extraction workflow, then queue-based large area processing, cost estimation, pause/resume checkpoints and explicit area/feature budgets. Never promise 100 km² in one minute without measured service capacity. |
| Drawing and illustration | ISO/plan vector SVG with layer controls, style and data-view presets (masterplan, figure-ground, Nolli-inspired footprint mask, land use and street hierarchy), palette, tree points, line weight, contours, labels and PNG export. 3D scene has per-layer offsets, visual styles and credited PNG. | Add street names where source data has names; hillshade, sun shadows and terrain sections with projection and scale controls. Nolli public interiors require surveyed access data; street classes do not imply pedestrian footfall. |
| CAD/BIM formats | GeoJSON, DXF, DAE, GeoTIFF, SVG and PNG. DAE is a terrain and building context model when terrain is ready. | Validate DAE import in supported SketchUp releases. Build and test one format at a time: GLB first, then IFC/3DM/FBX/STL if a reliable writer and conformance test are available. Never label DAE as native SKP. |

## Source and rights gates

For India, [NRSC Bhuvan Store](https://bhuvan-app1.nrsc.gov.in/2dresources/bhuvanstore2.php) lists urban land-use datasets at different scales and dates, with AMRUT coverage only for listed towns. Its map services need checked coverage, reuse rights and a verified vector analytic route before integration; a rendered WMS image is not a source for precise building-level area measurements. [WorldPop](https://www.worldpop.org/methods/populations/) provides modelled population grids rather than surveyed residents per building, and [Open-Meteo ERA5](https://open-meteo.com/en/docs/historical-weather-api) is regional weather reanalysis, not site-scale wind observation. These are candidates, **not connected feeds in this version**. Calibrated V/C and pedestrian flows require local traffic and pedestrian counts, origin–destination demand, suitable capacities and a validated network model. Building age and housing value require licensed local cadastre or transactions data; no such values are inferred from a building footprint.

- [Overture buildings schema](https://docs.overturemaps.org/schema/reference/buildings/building/) documents height, floors, roof attributes and associated building parts. The [buildings guide](https://docs.overturemaps.org/guides/buildings/) explains that Overture already combines OSM and several other open footprint sources, including Google Open Buildings. We should preserve per-feature source metadata instead of blindly stacking duplicate footprints.
- [Overture attribution](https://docs.overturemaps.org/attribution/) gives theme-specific licensing and upstream credits. Exports must carry the pinned release, source datasets, dates and ODbL obligations. A paid service can use open data, but its tile services, compute, hosting and source-specific terms still need review.
- [Mapzen Terrain Tiles registry](https://registry.opendata.aws/terrain-tiles/) describes a global bare-earth tile set and links its source-specific attribution. A mixed DEM is not necessarily lidar, and a finer output grid does not improve ground accuracy.
- Local architecture or municipality datasets should be integrated only after documenting geographic coverage, update cadence, accuracy, redistribution rights, and a field-level mapping. Never imply an unsupported city has authoritative LOD2, kerb geometry, or tree detection.

## Product rule

Every layer and export should show whether it is mapped, measured, estimated, or a user scenario. A format becomes a visible download only after a real importer/conformance check. An area size becomes a public promise only after extraction, generation and download have been measured across dense and sparse sites.

## Small-area urban measures in this release

The 1 km urban workspace clips building polygons to its square for approximate ground coverage, identifies green land-use polygons as unverified public-space candidates, finds explicitly tagged cycle routes, measures mapped-centreline walking reach from the square centre with an assumed 1.25 m/s speed, and casts 5° plan rays to mapped building outlines from a movable viewpoint. Polygon overlap, holes, missing access or buildings, and incomplete route connectivity affect the results. Sky view, residential population, real 15-minute destinations and observed V/C remain unavailable. The linked yearly Google Satellite Embedding data (10 m, Earth Engine registration required) could inform future land-cover change, not tree points. MODIS MCD12C1 (5.6 km) and NASA GLDAS daily skin temperature (27.8 km) are too coarse for this 1 km urban study; neither is integrated. Landsat surface temperature is a candidate for a future local heat view subject to date/cloud checks and appropriate access.
