# Site Context Studio 0.1.36

The Windows desktop installer build is described in [WINDOWS_DESKTOP.md](WINDOWS_DESKTOP.md). It bundles Node and the Python online reader; the local development server below still needs them installed separately.

Local site: [http://localhost:8787/](http://localhost:8787/). The Mac service serves this source and reports version 0.1.36 at `/api/health`. To install or restart it manually, run `./scripts/install-mac-service.sh` from this folder. Node.js 24+ and a Python 3.10+ online reader in `.venv` are needed for Overture capture; run `npm test` for the local checks. The separate friends-only HTTPS demo is documented in [DEMO_SHARING.md](DEMO_SHARING.md); free laptop-independent options are in [RENDER_FREE_DEMO.md](RENDER_FREE_DEMO.md) and [CLOUD_DEMO.md](CLOUD_DEMO.md). For broader hosting requirements, see [HOSTING_READINESS.md](HOSTING_READINESS.md) and the [security review](SECURITY_REVIEW.md). The server binds to `127.0.0.1` by default; set `HOST=0.0.0.0` inside a hosted container.

The site now has a pricing preview at `#/pricing` and a local account flow at `#/account`. Account email, scrypt password hash, hashed session tokens, editable profile fields and a personal workspace record are stored in `.local/accounts.sqlite`, which is excluded from source control. Sign-in does not persist site studies: capture jobs and terrain remain temporary process memory. Pro and Studio plans cannot be purchased yet. Before hosting accounts publicly, complete email verification and recovery, HTTPS, privacy/terms, durable study ownership and server-side entitlements; see [`../PRICING_PLAN.md`](../PRICING_PLAN.md). Set `SECURE_COOKIES=1` behind an HTTPS reverse proxy.

The workspace uses individual white icon buttons over the map, with no full-height panel behind them; its old horizontal heading is removed. Every rail button now has the same visible ink outline, and the rail, logo, search, site drawing and map action icons use one rounded 1.8 px line style. The hero city model scales to the available screen height, and the studio mark is smaller. About and Projects use compact viewport-aware spacing to keep their full content visible on common laptop displays; very short or narrow screens can scroll to access every button.

The site tool panel uses a white surface with restrained black type and blue action states. Its Data step puts the selected area above a five-layer checklist with accessible circular checks, an editable boundary and an anchored Get site data action. Each row remains wired to the live extraction setting, including Trees, which now refreshes the capture plan when toggled. Source details can be expanded without crowding the layer selection; progress, pause, cancel, retry, results and export remain available after capture.

The on-screen version badge and footer number have been removed. The build number remains in the server and an HTML data attribute so an open tab can detect updates without repeatedly reloading. The export list, height and movement evidence, massing controls, illustration controls, and urban analysis controls use the same white, black, gray and blue interface. Source-based map and 3D material colors remain data indicators. The 3D model control panel has a white background with dark labels; its height readout no longer repeats the mapped road total already shown beside the model.

The main 3D and urban 3D canvases use a true white renderer background, including image export; the separate illustration editor can still apply its Clay preset. Urban analysis no longer repeats the active metric in a floating card over the map or model. The selected tool's evidence and source notes remain in its sidebar.

Capture progress is a single filling blue line with a walking marker; Pause and Cancel remain as icon controls, while the live status and numeric value are available to assistive technology. The panel omits the duplicated city buttons and coordinate field; the map search bar accepts worldwide place names or latitude and longitude. Enter a name and submit to select from matching places; selecting a place moves the map without changing the drawn boundary. Place search uses OpenStreetMap Nominatim via the local server, with attribution, caching and request throttling; it depends on that service being available. Layer capture estimates are in the source details disclosure. The Results step no longer shows the oversized tree image form or duplicated urban analysis KPI card. Tree image review opens from Urban Analysis as a separate map tool, and urban analysis JSON downloads from that tool. Sources and important method limits remain available where relevant; repeated helper copy has been removed.

The landing page uses the supplied `reference-city-block-package.zip`: its original daytime geometry and colours are preserved. Click the left residence for About, the tall middle tower for the map workspace, or the right tower for Projects. Drag to orbit; the model has a fixed scale, and there is no day/night theme switch. The workspace UI uses white, black and blue while captured 3D geometry retains its original material colours. The Illustrated map control opens the graphics editor's captured masterplan with the Clay drawing preset. It requires captured layers, so before a capture the control points you toward the site boundary and Data steps.

The Area stage now offers **Free polygon** and **Square / rectangle**. In the second mode, one map click places a 400 m square; drag any corner to adjust its width and height while keeping the opposite corner fixed. The first mode still lets you click to place vertices, and you can drag individual vertices before finishing. Both modes produce the same site polygon for data capture, 2D/3D study and export. **Edit** opens a draft of the captured boundary and **New site** starts an empty draft without discarding the existing site. Cancel editing or press Escape to keep the existing site and captured data. Applying a changed boundary clears the old capture and prompts you to fetch data for the new area; applying an unchanged boundary keeps the existing capture.

The main 3D view, graphics editor scheme and urban 3D view now render a closed solid base with a smooth edge following the drawn polygon, including when the DEM pixel mask has gaps at its edge. Its side faces have seven illustrative strata and subtle horizontal seams. Without a DEM, the selected boundary has a level solid base rather than measured relief. The 3D PNG includes the base; the package’s COLLADA model includes a solid cut beneath the DEM or level ground. The vertical cut thickness and bands are graphic conventions, not measured geology.

The study now includes an analysis catalogue grouped by Form, Use and people, Movement, and Environment. Results with evidence are linked to the 2D map and 3D model: building height evidence, clipped street length, mapped land use, tree points, site area, and optional DEM relief. Every visible figure has a method note and source list. Unavailable analyses say which extra inputs are needed; road centrelines are never passed off as traffic counts or pedestrian flow. A separate JSON download captures site metrics, missing fields and source provenance.

The graphics editor has an orbitable 3D scheme with context and clay styling, common and individual layer separation, dotted guides and an editing cube that is excluded from the PNG. Its 3D PNG includes attribution and the `kaniks-studio` watermark. The ordinary 3D context view has an entry point into this editor. The vector graphic editor now includes masterplan, figure–ground, Nolli-inspired footprint mask, land use, and mapped street hierarchy presets. Tree points are drawn in SVG. These presets use the currently captured features; missing source features remain missing. Footfall is explicitly unavailable until counted or calibrated. SVG and 4800 × 3400 PNG retain the studio watermark.

Urban Analysis opens from the ▥ navigation tool after you draw a polygon and fetch site data. It uses the same captured polygon, features, optional terrain and provenance; there is no second 1 km capture. A map and orbitable 3D model show source-backed Form, Use and People, Movement, and Environment layers. Its controls use the new light UI with blue accents; the map features, data legends, 3D road overlays and exported analysis drawings use the previous data palettes, including green trees, warm land use and red-to-blue route choice. The 3D view offers Orbit, ISO and Top views; five independent layer switches determine the visible captured data. Its 3D PNG, 2D SVG/PNG and GeoJSON use your polygon, and the latter records the selected and visible layers. Calculations clip building and green coverage and road lengths to the drawn polygon, including concave boundaries. The 5/10/15-minute reach follows mapped roads at an assumed 1.25 m/s from an interior point and ends at the boundary, without claiming a true isochrone; planar sightlines stop at mapped footprints or the boundary. The browser-only 800 m length-weighted network-choice proxy is not angular segment choice or observed pedestrian volumes. Missing population and traffic inputs are clearly labelled. If a layer was excluded from the original site capture, the urban view asks you to include it in the Data stage and fetch the site again.

Clear satellite imagery is shown automatically when the site owner supplies a licensed MapTiler key as the `MAPTILER_KEY` environment variable for the server and allows the site's HTTP origin on that key. Visitors do not paste URLs or keys. Without a configured imagery account, only the coarse regional overview is available; it cannot identify individual trees. Map imagery display does not itself grant imagery-analysis rights.

Draw a boundary, select building, road, water, land use and tree layers, then fetch mapped features from Overture Maps and OpenStreetMap. Tree points already mapped in OSM appear in 2D, the 3D view and the GIS/COLLADA ZIP. A separate imagery control accepts a licensed, north-up PNG/JPEG/WebP cropped to the selected bounding rectangle. It proposes dots from green shapes **inside the polygon**; click incorrect dots to reject them, then add the reviewed set. The image and proposals are processed in browser memory. Their accepted features are merged into the exported GeoJSON, DXF, DAE, provenance and summary in the browser, without sending them to the server.

The colour detector is experimental: it can mistake grass and roofs for trees or combine adjoining crowns. The 3D model uses symbolic lightweight markers, not measured tree crowns. **This release does not fetch or screenshot aerial imagery automatically and does not run DeepForest.** A high resolution imagery provider with explicit analysis rights and a verified browser-compatible detection model are needed before offering automatic individual-tree detection for every drawn area. Displaying a MapTiler or Google basemap does not grant permission to extract trees from those tiles.

An idle local tab refreshes when the server reports a newer version. A tab with a drawn area, capture or open urban study instead shows a refresh button, since reloading discards session-memory results.

No capture is written to disk. The server holds fetched map data and optional terrain tiles in process memory for up to two hours; deleting or restarting the session clears them. The browser does not use localStorage, IndexedDB or a service worker for captures or keys. Imagery never leaves the browser. A completed download is the only intentional persistent output, created when the user requests it. The pre-existing `local-data/` benchmark files are not used by this server. An older service on `8787` must be updated with the installer above before it serves this build.

This local prototype still uses a server process for public map-data reads and ZIP generation. Account login exists, but site captures are anonymous and are not isolated by account, so it is not ready for a public multiuser launch. Building heights, terrain and image proposals need source and field verification. The generated DAE is not a native SketchUp file.
